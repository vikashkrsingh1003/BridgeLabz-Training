FundooNotes

Project Architecture, Configuration and Postman Testing Guide

Application type: Spring Boot microservices

Version context: Spring Boot 3.5.x, Java 17-compatible modules

Document purpose: Explain the running system, required infrastructure, startup sequence, authentication flow, password-reset email flow, and Postman endpoints.

Security note: Credentials are intentionally redacted from this guide. Keep the real .env file local and never commit it.

1. System Overview

FundooNotes is a note-management application split into independently runnable Spring Boot services. Eureka provides service discovery, the API Gateway provides the client entry point, and separate services own authentication, notes, reminders, and administration.

ComponentPortResponsibility
Eureka Server8761Service registry and discovery
API Gateway8080Single API entry point, routing and circuit breakers
Auth Service8081Registration, login, JWT and password reset tokens
Notes Service8082Notes, tags, search, state changes and export
Reminder Service8083RabbitMQ consumers and Gmail email delivery
Admin Server8085Spring Boot Admin monitoring

2. Request Flow

  1. Postman sends requests to http://localhost:8080.
  2. The API Gateway routes /auth/** to auth-service and /notes/** or /tags/** to notes-service through Eureka.
  3. Auth service stores users and reset tokens in MySQL and returns JWT tokens.
  4. Notes service validates JWTs and stores notes/tags in MySQL. It uses Redis for data operations configured by the service.
  5. Notes and auth publish messages to RabbitMQ. Reminder service consumes them.
  6. Reminder service sends password-reset and note-reminder emails through Gmail SMTP.

3. Required Infrastructure

4. Environment Configuration

The root .env contains local values consumed through Spring placeholders. The important keys are:

DB_URL=jdbc:mysql://localhost:3306/fundoonotesdb
DB_USERNAME=<mysql-user>
DB_PASSWORD=<mysql-password>
JWT_SECRET=<long-random-secret>
RABBIT_MQ_HOST=localhost
RABBIT_MQ_PORT=5672
RABBIT_MQ_USERNAME=guest
RABBIT_MQ_PASSWORD=guest
FUNDOO_MAIL_USERNAME=<gmail-address>
FUNDOO_MAIL_PASSWORD=<google-app-password>
Gmail: use a Google App Password, not the normal Gmail account password. Store the 16-character value without spaces or quotes, then restart reminder-service.

5. Startup Order

  1. Start MySQL and create database fundoonotesdb.
  2. Start Docker Redis and RabbitMQ.
  3. Start eureka-server.
  4. Start auth-service, notes-service and reminder-service.
  5. Start api-gateway and admin-server.

Run each service in a separate terminal:

cd eureka-server && sh ./mvnw spring-boot:run
cd auth-service && sh ./mvnw spring-boot:run
cd notes-service && sh ./mvnw spring-boot:run
cd reminder-service && sh ./mvnw spring-boot:run
cd api-gateway && sh ./mvnw spring-boot:run
cd admin-server && sh ./mvnw spring-boot:run

6. Authentication Flow

Register or log in first. The response contains a JWT. In Postman, use the token as:

Authorization: Bearer YOUR_JWT_TOKEN

Auth endpoints are public. Notes and tags endpoints require the JWT.

9. Health Checks and Troubleshooting

GET http://localhost:8761/actuator/health
GET http://localhost:8080/actuator/health
GET http://localhost:8081/actuator/health
GET http://localhost:8082/actuator/health
GET http://localhost:8083/actuator/health
GET http://localhost:8085/actuator/health
  • Gateway returns 503: check that auth/notes are running and registered in Eureka.
  • Auth or notes cannot start: check MySQL on port 3306 and database name.
  • Reminder health is DOWN: inspect the mail component. A Gmail 535-5.7.8 error means the App Password is invalid, belongs to another account, or was not loaded after restart.
  • Rabbit listener errors: confirm RabbitMQ is running on port 5672 and inspect queues in the management UI.
  • Port already in use: find the process with lsof -nP -iTCP:PORT -sTCP:LISTEN before starting another instance.

10. Password Reset Email Flow

  1. Client calls POST /auth/forgot-password.
  2. Auth service creates or updates a reset token in MySQL.
  3. Auth publishes email|resetToken to RabbitMQ queue password-reset-queue.
  4. Reminder service consumes the queue.
  5. Reminder service sends the token using Gmail SMTP.
  6. Client submits the emailed token to POST /auth/reset-password.
Expected test result: the forgot-password API may return immediately with 200 OK; email delivery happens asynchronously. Confirm delivery in the recipient inbox and check reminder-service logs if it does not arrive.
